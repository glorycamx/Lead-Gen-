# Compliance Notes

## Overview

The Massachusetts Solar + Mass Save Lead Bot is designed to generate leads in a **strictly compliant** manner. This document outlines what the system does and does NOT do to ensure legal and ethical operation.

---

## What This System Does NOT Do

### Data Collection Restrictions

1. **No Private Data Scraping**
   - Does not scrape websites for personal information
   - Does not harvest contact information from social media
   - Does not access non-public databases

2. **No Access Control Bypass**
   - Does not bypass login pages
   - Does not circumvent paywalls
   - Does not solve CAPTCHAs
   - Does not access restricted areas of websites

3. **No Automated Outreach**
   - Does not auto-send SMS messages
   - Does not auto-send emails
   - Does not make robocalls
   - Does not submit web forms automatically

4. **No Imagery Analysis Without License**
   - Does not analyze satellite/aerial imagery for roof condition
   - Does not estimate solar viability from photos
   - Does not assess tree coverage or shading
   - Does not make inferences about property condition from images

---

## What This System IS Allowed To Do

### Data Ingestion

1. **User-Provided Data**
   - Process CSV files uploaded by authorized users
   - Import CRM exports with proper consent
   - Ingest assessor data legally obtained by the user

2. **Open Data Sources**
   - Access Massachusetts open data portals where Terms of Service permit
   - Use municipal open data with automated download permission
   - Cache public records for performance

3. **Geocoding**
   - Use lawful geocoding services with user-provided API keys
   - Perform ZIP code radius targeting with open source data

### Output Generation

1. **Lead Scoring**
   - Calculate fit scores based on property characteristics
   - Flag program eligibility based on available data
   - Rank leads by score and filters

2. **Draft Generation**
   - Create outreach **drafts** for human review
   - Store drafts in database for later access
   - Never send any communication automatically

3. **Exports**
   - Generate CSV files for manual use
   - Store data in local SQLite database
   - Optionally push to user-owned Google Sheets

---

## Human-in-the-Loop Requirements

All outreach generated by this system requires **human approval** before any contact is made:

1. **Door Knock Notes**: Review and personalize before visiting
2. **SMS Drafts**: Must be manually sent by a human
3. **Email Drafts**: Must be copied and sent manually

The system displays clear warnings throughout the UI that drafts are for review only.

---

## Messaging Compliance

### Prohibited Language

The AI-generated content avoids:

- "You qualify" / "You're eligible"
- "Guaranteed savings"
- "100% free" (without qualification)
- "Limited time" urgency tactics
- "You've been selected" (false exclusivity)
- Government program misrepresentation

### Required Language

Mass Save messaging includes compliant phrasing:

- "Free assessment available in many cases"
- "Rebates and incentives vary by home and eligibility"
- "We can help you understand your options"
- "Subject to eligibility requirements"

### Opt-Out Requirements

All SMS and email drafts include:

- Clear sender identification
- Opt-out instructions ("Reply STOP to opt out")
- Contact information

---

## Data Privacy

### Data Storage

- All data stored locally in SQLite
- No cloud storage of personal information without consent
- No sharing of data with third parties

### Data Retention

- User controls data retention
- Delete leads via dashboard
- Export before deletion if needed

### Data Sources

Users must ensure they have legal rights to any data uploaded:

- Public assessor records
- Legitimately obtained parcel data
- Own CRM exports
- Permitted open data sources

## Legal References

This system is designed to comply with:

- **CAN-SPAM Act**: Commercial email requirements
- **TCPA**: Telephone Consumer Protection Act
- **Massachusetts General Laws Chapter 93A**: Consumer protection
- **Mass Save Program Rules**: Energy efficiency program guidelines
- **CCPA/CPRA**: California privacy laws (if applicable)

## Audit Trail

The system maintains logs of:

- All data imports (file name, rows processed, errors)
- All exports (date, row count, file path)
- Pipeline runs (timestamp, status, statistics)
- Status changes on leads (history tracking)

## Recommendations

1. **Verify Data Sources**: Ensure all uploaded data was legally obtained
2. **Review Drafts**: Always review and personalize AI-generated content
3. **Maintain Records**: Keep records of consent and data sources
4. **Train Staff**: Ensure anyone using the system understands compliance requirements
5. **Regular Audits**: Periodically review exports and outreach for compliance
